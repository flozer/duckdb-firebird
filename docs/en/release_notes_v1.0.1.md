# duckdb-firebird v1.0.1 - Release notes

Patch release. No API changes.

## Fix

- **`ReconcileViewColumnTypes` defensive fallback (#36)** — the function's
  internal object-type check (`LookupObjectType`) could, on a rare
  connection-level failure classifying an object, skip the live-describe
  reconciliation step entirely. That reconciliation is what prevents the
  v1.0.0-era #33 crash (a view's frozen catalog metadata claiming a wider
  type than what an aggregate like `SUM()` actually produces at runtime).
  Now, whenever the object type can't be positively confirmed as
  non-view — whether `LookupObjectType` throws or simply finds no
  matching row — the function falls through to the same defensive
  live-describe probe used for a confirmed view, instead of skipping
  reconciliation. Correctness-only change; no observable behavior change
  for any query that previously worked correctly.
